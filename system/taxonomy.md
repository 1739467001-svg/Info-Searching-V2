# 🗂️ 分类体系：领域 · 类型 · 关系 · 命名

> 何时读：新建条目、给条目选领域/类型、声明关系时。
> 本文件与 `tools/kblib.py` 顶部的常量一一对应；改其中一处必须同步改另一处。

## 1. 领域（domain）——决定条目放在 `kb/` 下的哪个目录

| id | 名称 | 范围 | 边界提示 |
|---|---|---|---|
| `formal-sciences` | 🧮 形式科学 | 数学、逻辑、统计学、理论计算机科学 | 概率、信息论的数学部分放这里 |
| `natural-sciences` | 🔭 自然科学 | 物理、化学、天文、地球科学 | 生物学放 `life-medicine` |
| `life-medicine` | 🧬 生命与医学 | 生物学、遗传、生态、医学与健康 | |
| `tech-ai` | 🤖 技术与 AI | 计算机、人工智能、互联网、电子与工程技术 | 偏"怎么造"放这里；偏"数学原理"放形式科学 |
| `social-sciences` | 🏛️ 社会科学 | 经济、心理、社会、政治、法律、教育 | |
| `humanities` | 📜 人文艺术 | 哲学、宗教、语言、文学、艺术、传统文化 | |
| `history` | ⏳ 历史 | 历史事件、时代、文明与史学概念 | |
| `geography` | 🌍 地理与地区 | 自然地理、人文地理、国家与地区 | |
| `business` | 💼 商业与产业 | 企业、产业、金融、产品与商业模式 | |
| `thinking` | 🧠 思维与方法 | 心智模型、学习方法、决策与认知工具 | |

**跨领域概念怎么办？** 只放一个"主领域"（谁最常用这个概念、或它诞生于哪个学科），其余领域用 `tags` 标注，再用 `related` / `applies-to` 关系连过去。**绝不在两个领域各写一份。**

例：「熵」诞生于热力学 → `natural-sciences`；信息熵的内容写在同一条目的"别搞混"章节里；若将来单独写「信息熵」，两者用 `contrasts` 连接。

## 2. 类型（kind）——决定用哪个模板、需要哪些章节

| kind | 名称 | 典型输入 | 必需的八个维度（章节标题关键词） |
|---|---|---|---|
| `concept` | 概念 | 熵、注意力机制、边际效应、丝绸之路 | 是什么 · 为什么 · 怎么运作 · 从哪来 · 看例子 · 别搞混 · 怎么看 · 怎么用 |
| `topic` | 专题 | 机器学习全景、Solana 生态 | 是什么 · 版图 · 脉络 · 关键概念 · 代表 · 趋势 · 怎么看 · 学习路径 |
| `event` | 事件 | 安史之乱、工业革命 | 是什么 · 背景 · 经过 · 人物与力量 · 影响 · 史料与争议 · 别搞混 · 怎么用 |
| `person` | 人物 | 香农、张骞 | 是谁 · 生平 · 贡献 · 思想 · 影响 · 评价 · 别搞混 · 怎么用 |
| `place` | 地点 | 河西走廊、撒马尔罕 | 在哪里 · 自然 · 人文 · 历史 · 经济 · 文化 · 别搞混 · 今日 |
| `work` | 作品 | 书、论文、电影、课程 | 基本信息 · 主旨 · 结构 · 核心观点 · 评价 · 适合谁 |

所有类型在成熟度 ≥ 标准时，还必须有：**自测 · 关联 · 来源 · 我的思考**。

**专题（topic）的纪律**：专题是"地图"，不是"仓库"。它负责讲清版图和脉络，具体概念只写一两句并链接到概念条目；概念还没建就登记为关系目标，让它进入研究前沿。

## 3. 关系（relations）——写在条目 front-matter 里

写法：`- 关系类型: 目标id | 备注（可选，说明为什么有这条关系）`

| 关系 | 正向读法（A → B） | B 页面上显示为 | 用途 |
|---|---|---|---|
| `is-a` | A 是一种 B | 下位/实例 | 上下位分类 |
| `part-of` | A 属于 B 的一部分 | 包含 | 整体-部分 |
| `based-on` | 学 A 之前要先懂 B | 后续延伸 | **学习路径**由它推导 |
| `leads-to` | A 催生/演化出 B | 源自 | 历史演化、因果 |
| `contrasts` | A 区别于 B（易混） | 区别于 | 辨析 |
| `applies-to` | A（方法）应用于 B（领域/问题） | 所用方法 | 方法与场景 |
| `influenced` | A 影响了 B | 受其影响 | 人物、思想、事件 |
| `located-in` | A 位于 B | 境内/包含 | 地理 |
| `related` | A 与 B 相关 | 相关 | 兜底，能用具体关系就别用它 |

规则：

1. **只声明出链**。反向链接由脚本自动生成，不要在两边重复写。
2. 目标条目**可以还不存在**。不存在的目标会自动出现在 [`graph/frontier.md`](../graph/frontier.md) 的待建队列里——这是知识库生长的主要方式。
3. 每个条目建议 3–8 条关系。太少会成为孤岛；太多说明关系不够具体。

## 4. 命名（id）

- 小写英文 kebab-case，等于文件名：`attention-mechanism.md`
- 优先使用该概念**通行的英文名**（便于中英文检索与对照）；没有通行英文名的用拼音：`rizhu`
- 中文名写在 `title`，其他叫法（简称、旧译名、英文缩写）写进 `aliases`——`kb.py find` 依赖它们找到条目
- 同名异义时加限定词：`entropy`（热力学/统计物理）与 `information-entropy`（信息论）

## 5. 成熟度（status）与置信度（confidence）

两个维度互相独立：成熟度衡量"写得全不全"，置信度衡量"可信不可信"。

| 成熟度 | 含义 | 量化底线（`kb.py check` 强制） |
|---|---|---|
| 🌱 `draft` 草稿 | 有卡片和至少一个来源，可以先用 | ≥1 来源 |
| 🌿 `standard` 标准 | 八维齐全、可独立学习 | ≥5 来源、≥1 个 S1、≥3 道自测题、全部必需章节 |
| 🌳 `deep` 深度 | 能当作该主题的入门参考 | ≥8 来源、≥2 个 S1、≥5 道自测题、全部必需章节 |

置信度规则见 [source-policy.md](source-policy.md)。
