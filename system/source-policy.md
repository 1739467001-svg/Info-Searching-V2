# 🔎 来源与核实规范（准确性的保险丝）

> 何时读：引用任何来源、给条目定置信度、遇到来源互相矛盾时。
> 约法三章第一条是**准确性**。本文件把它拆成可执行、可校验的规则。

## 1. 三条红线（违反任何一条，条目不得合入）

1. **不编造来源**：只列出本次**实际访问并读到内容**的来源。凭记忆想起的论文、书、链接，必须检索确认存在后才能写入。
2. **不把记忆当事实**：AI 训练记忆里的数字、日期、引文一律视为"待核"，核实前用【待核】标注，或干脆不写。
3. **不隐藏分歧**：来源之间有冲突时，写出冲突，不要悄悄挑一个。

## 2. 来源分级（Tier）

| 级别 | 是什么 | 例子 |
|---|---|---|
| **S1** 一手 / 权威 | 原始出处，或经同行评审、编辑审定的权威参考 | 原始论文（含预印本，但需注明未经同行评审）、官方文件与统计、标准、学术专著、正式出版的大学教材（如《动手学深度学习》）、权威百科（斯坦福哲学百科、不列颠百科）、联合国教科文组织等机构页面 |
| **S2** 专业二手 | 有专业门槛、可追责的转述与综述 | 综述论文、高校课程讲义、知名研究机构/企业的技术报告与博客、权威媒体的深度报道、专业科普（如 3Blue1Brown） |
| **S3** 一般二手 | 门槛低、可能有误，但有线索价值 | 维基百科、百度百科、知乎、个人博客、问答社区、视频 |

- 维基类百科是**线索入口**而非终点：可以用来找原始出处，但核心论断应追到 S1/S2。
- S3 可以用来呈现"大众怎么理解/误解"，这本身是"别搞混"章节的素材。

## 3. 核实方式（Verify）

每个来源必须如实标注你**实际读到了什么**：

| 标注 | 含义 | 可支撑的内容 |
|---|---|---|
| `核实：全文` | 打开并阅读了相关正文 | 正文中的任何细节 |
| `核实：摘要` | 只读到摘要、检索结果摘要或目录页 | **仅限**摘要里明确出现的内容 |
| `核实：转引` | 没读到原文，是从另一个来源转引的 | 必须同时写明转引自哪里；不能单独支撑核心论断 |

> 为什么要有这个字段：网络环境、付费墙、地区限制都可能让你读不到原文。如实标注比假装读过更有价值——读者能据此判断哪些论断还值得再核一遍。

## 4. 引用格式（脚注）

正文中在论断后标 `[^key]`，在「来源」章节集中定义：

```markdown
[^vaswani2017]: **S1** · Vaswani et al., *Attention Is All You Need*, NeurIPS 2017 · <https://arxiv.org/abs/1706.03762> · 核实：摘要 · 访问 2026-10-06 · 支撑：Transformer 定义；英德翻译 BLEU 28.4
```

必备要素：**分级 · 作者/机构 · 标题 · 出处与年份 · 链接（或 ISBN）· 核实方式 · 访问日期 · 支撑了哪些论断**。

`kb.py check` 会检查：分级与核实方式是否齐全、正文引用与定义是否一一对应、有没有链接。

## 5. 论断标注

在正文的关键论断后，用以下标签说明"这件事的确定程度"：

| 标签 | 含义 | 何时使用 |
|---|---|---|
| 【共识】 | 学界/业界普遍接受，多个独立 S1/S2 一致 | 定义、经典结论 |
| 【主流】 | 多数人支持，但存在有分量的不同意见 | 解释性观点、主流学派结论 |
| 【争议】 | 存在实质分歧，各方都有依据 | 必须在"怎么看"章节展开各方 |
| 【待核】 | 有线索但尚未找到可靠来源 | 临时状态；`kb.py check` 会持续提醒 |

不必每句都标——只标那些读者可能会拿去引用、或者容易被误解的论断。

## 6. 交叉核实规则

- **核心论断**（定义、关键数字、关键日期、因果判断）至少有 **2 个相互独立**的来源支撑。两篇文章引用同一个出处 = 1 个来源。
- **数字**：能复算的必须复算（例如百分比、单位换算、公式代入），并在"看例子"章节写出计算过程。
- **引文**：名人名言、经典原文必须追到出处；追不到就写"常被归于某某，未找到原始出处"。
- **时间敏感内容**（模型排名、市场数据、政策、人物现职）：写明"截至 YYYY-MM"，并设置 `review_after`。

## 7. 来源冲突时

1. 先看是不是**口径不同**（定义范围、统计年份、单位、学派）——多数"冲突"其实是口径问题，写清口径即可。
2. 真冲突：按"更一手、更新、更可追责"排序采信，但在正文或"怎么看"章节**写出另一种说法及其来源**。
3. 无法判断：标【争议】，并列呈现。

## 8. 置信度判定

| 置信度 | 条件（全部满足） | `kb.py check` 的量化底线 |
|---|---|---|
| **高** | 核心论断均有 ≥2 个独立来源；其中至少一个 S1；核心论断没有只靠"转引"支撑的；无未解决的冲突 | ≥3 来源且 ≥1 个 S1 |
| **中** | 核心论断有来源支撑，但部分只有单一来源，或依赖 S2/S3、或只核实到摘要层面 | ≥2 来源 |
| **低** | 来源不足、以 S3 为主，或存在未解决的冲突 | — |

脚本只能检查"数量"，**"核心论断是否被交叉印证"需要写作者诚实判断**。拿不准时取较低一档。

## 9. 检索矩阵（兼听则明）

研究一个主题时，按下表覆盖**至少 4 类**来源，并且**中文与英文都要检索**：

| 类别 | 检索什么 | 价值 |
|---|---|---|
| 学术 | 原始论文、综述、学术专著 | 准确的定义、机制与证据 |
| 权威参考 | 百科全书、教材、标准、官方机构 | 规范定义、口径 |
| 官方/一手 | 机构官网、产品文档、统计数据、法规原文 | 事实与数字 |
| 专业解读 | 课程讲义、技术博客、专业科普 | 讲法与直觉 |
| 中文社区 | 知乎、专业公众号、中文百科 | 中文语境下的理解与常见误解 |
| 批评与反方 | "criticism of X"、"X 争议"、"X 误区" | 平衡视角 |

在「来源」章节开头用一行写明本次覆盖了哪几类、哪些语种，以及有哪些想查但没查到的（例如"某站点无法访问"）。
