# /research —— 从一个词到一个条目

输入：`$ARGUMENTS`（一个名词、概念或问题）

完整流程见 `system/research-protocol.md`（**现在就读它**）；来源规则见 `system/source-policy.md`；写法见 `system/writing-standard.md`。下面是执行清单：

## 清单

1. **查重**：`python3 tools/kb.py find <词>`，再用英文名查一次。
   - 已存在 → `kb.py card <id>` 回答用户；如果用户要更深，转 `/deepen <id>`。到此结束。
2. **拆题**：确定 `domain`、`kind`、要讲的义项（同名异义要选定一个）；按该类型的八个维度各列 1–2 个问题；列出前置知识与易混概念。
3. **多源检索**：覆盖 ≥4 类来源（学术 / 权威参考 / 官方 / 专业解读 / 中文社区 / 批评与反方），中英文都查。边查边记：来源、分级 S1/S2/S3、核实方式（全文/摘要/转引）、它支撑哪个论断。
4. **交叉核实**：核心论断 ≥2 个独立来源；数字复算；冲突先查口径；查不实的标【待核】或不写。**不把训练记忆当事实。**
5. **建文件**：`python3 tools/kb.py new <kind> <id> --domain <领域> --title <中文名> --en <英文名>`
6. **写作**：先写八个维度，最后写卡片与 summary；关键论断加脚注；例子可复算；类比写失效边界；写 ≥3 道考理解的自测题；「我的思考」只留引导问题。
7. **关联**：front-matter 中声明 3–8 条出链（based-on / contrasts / is-a / leads-to …）；`kb.py grep <中文名>` 看已有条目是否应补一条指向新条目的关系。
8. **校验**：`python3 tools/kb.py index && python3 tools/kb.py check`，必须 0 错误。如实设定 `status` 与 `confidence`（拿不准取低一档）。
9. **回复用户**：给卡片级的回答（30 秒版 + 要点）+ 条目链接 + 本次置信度与仍待核实的点。不要贴全文。
10. **提交**（用户要求或会话约定时）：`kb(<领域>): 新增「中文名」<成熟度>，<N> 来源`
